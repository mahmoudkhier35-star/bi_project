# Data Dictionary
## Retail & E-Commerce Platform

This document describes the columns in the raw transaction export (`data/raw/Pakistan Largest Ecommerce Dataset.csv`), their types, business meaning, observed formatting issues, and how they map to target warehouse tables.

---

### 1. `item_id`
- **Description:** Line-item transaction identifier generated by the checkout system. Unique across every valid row.
- **Raw Type:** `float64` (contains NaNs in empty filler rows).
- **Clean Type:** `BIGINT` (Primary Key in `OrderDetails`).
- **Nulls:** 0 in valid data rows (464,051 in empty trailing rows).
- **Unique Count:** 584,524.

### 2. `status`
- **Description:** Order fulfillment status at the time of export.
- **Raw Type:** `object`.
- **Clean Type:** `VARCHAR(50)`.
- **Main Values:**
  - `complete` (233,685 items / 169,502 orders): Delivered and finalized.
  - `canceled` (201,249 items / 148,656 orders): Canceled before shipment or dropped at checkout.
  - `received` (77,290 items / 35,806 orders): Placed in system, pending dispatch.
  - `order_refunded` (59,529 items / 49,067 orders): Returned and refunded post-delivery.
  - `refund` (8,050 items / 4,091 orders): Refund initiated.
  - `cod` (2,859 items): Pending COD confirmation.
  - `paid` (1,159 items): Payment received, awaiting dispatch.
  - Minor statuses: `closed`, `payment_review`, `pending`, `processing`, `holded`, `fraud`, `exchange`.
  - Nulls/Missing: 15 rows null, 4 rows with string `\N`.
- **Cleaning:** Replaced `\N` and nulls with `'unknown'`. Mapped into 4 main operational groups: Completed, Canceled, Refunded, and Pending / In Progress.

### 3. `created_at`
- **Description:** Timestamp when the order was placed.
- **Raw Type:** `object` (format: `M/D/YYYY`).
- **Clean Type:** `DATE` (stored in `Orders.order_date`).
- **Date Range:** `2016-07-01` to `2018-08-28`.

### 4. `sku`
- **Description:** Stock Keeping Unit code identifying the product.
- **Raw Type:** `object`.
- **Clean Type:** `VARCHAR(150)` (stored in `Products.sku`).
- **Unique Count:** 84,889.
- **Nulls:** 20 rows missing SKU.
- **Cleaning:** Imputed missing values with `'UNKNOWN_SKU'`.

### 5. `price`
- **Description:** Unit list price in PKR.
- **Raw Type:** `float64`.
- **Clean Type:** `DECIMAL(12,2)`.
- **Range:** 0.00 to 1,012,626.00 PKR (average 6,348.75 PKR).
- **Anomalies:** 2,232 items have `price = 0.00` (promotional giveaways or free samples).
- **Cleaning:** Flagged with `is_promotional_sample = 1`.

### 6. `qty_ordered`
- **Description:** Quantity of units ordered.
- **Raw Type:** `float64`.
- **Clean Type:** `INT`.
- **Range:** 1 to 1,000 units (average 1.30 units).
- **Anomalies:** 42 items have `qty_ordered > 100` (bulk/wholesale orders).
- **Cleaning:** Converted to integer. Flagged wholesale orders (`qty_ordered >= 50`).

### 7. `grand_total`
- **Description:** Order-level total invoice amount including discounts and shipping.
- **Raw Type:** `float64`.
- **Clean Type:** `DECIMAL(18,2)` (stored in `Orders.grand_total`).
- **Important Note:** In multi-item orders (81,854 orders), `grand_total` is repeated across every line item. Summing this column directly across the raw file gives **4.986B PKR**, whereas the true distinct order sum is **3.896B PKR** (a 1.09B PKR inflation).
- **Cleaning:** Handled at the order header grain in `Orders`. Line-item revenue is computed separately in `OrderDetails` as `(price * qty_ordered) - discount_amount`.

### 8. `increment_id`
- **Description:** Customer-facing order number.
- **Raw Type:** `object` (e.g. `100147443`).
- **Clean Type:** `VARCHAR(50)` (Primary Key in `Orders`, Foreign Key in `OrderDetails`).
- **Unique Count:** 408,782 orders.

### 9. `category_name_1`
- **Description:** Merchandise category.
- **Raw Type:** `object`.
- **Clean Type:** `VARCHAR(100)` (stored in `Categories.category_name`).
- **Unique Count:** 16 categories.
- **Anomalies:** 7,850 rows contain the string `\N`, and 164 rows are null.
- **Cleaning:** Known categories were recovered using existing SKU history (20 SKUs recovered). Remainder assigned to `'Uncategorized'`.

### 10. `sales_commission_code`
- **Description:** Affiliate or sales agent code.
- **Raw Type:** `object`.
- **Clean Type:** `VARCHAR(50)`.
- **Nulls:** 137,178 nulls + 265,348 rows with `\N` (total missing: 68.9%).
- **Cleaning:** Standardized to `'NONE'`.

### 11. `discount_amount`
- **Description:** Discount amount applied to the line item in PKR.
- **Raw Type:** `float64`.
- **Clean Type:** `DECIMAL(12,2)`.
- **Range:** -599.50 to 90,300.00 PKR.
- **Anomalies:** 3 rows had negative discount values.
- **Cleaning:** Converted negative values using `abs()`.

### 12. `payment_method`
- **Description:** Payment method used for the transaction.
- **Raw Type:** `object`.
- **Clean Type:** `VARCHAR(50)` (stored in `PaymentMethods.payment_method_name`).
- **Unique Count:** 18 methods (`cod`, `payaxis`, `easypay`, `bankalfalah`, `jazzwallet`, etc.).
- **Cleaning:** Lowercased, stripped whitespace, and stored in master lookup `PaymentMethods`.

### 13. `Working Date`
- **Description:** Matches `created_at` in 100% of rows.
- **Cleaning:** Used to verify dates, then consolidated into `order_date`.

### 14. `BI Status`
- **Description:** Legacy reporting column (`Net`, `Gross`, `Valid`, `#REF!`).
- **Cleaning:** 1 row had `#REF!` from an Excel formula error; corrected to `'Net'`.

### 15. ` MV `
- **Description:** Merchandise value string with commas and spaces (e.g. `' 1,950 '`).
- **Cleaning:** Redundant with `price * qty_ordered`. Stripped formatting and verified against line item totals.

### 16. `Year`, `Month`, `M-Y`, `FY`
- **Description:** Pre-extracted calendar and fiscal attributes.
- **Cleaning:** Normalized and derived from `order_date`.

### 17. `Customer ID`
- **Description:** Customer account number.
- **Raw Type:** `float64`.
- **Clean Type:** `INT` (Primary Key in `Customers`).
- **Unique Count:** 115,326.
- **Nulls:** 11 rows missing customer ID.
- **Cleaning:** Imputed to surrogate key `0` (`'Guest / Unregistered'`).

### 18. `Customer Since`
- **Description:** First purchase / account creation cohort (`YYYY-M`).
- **Cleaning:** Stored as an attribute in `Customers`.

### 19. `Unnamed: 21` through `Unnamed: 25`
- **Description:** 5 trailing columns containing 100% nulls across all rows.
- **Cleaning:** Dropped during ingestion.
